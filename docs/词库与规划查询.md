# 词库与规划查询

以下是 Electron Main 使用的本机 DTO，不是新增的 LMCP 规范方法。公共字典只读，每次业务写入均由 Core 在单个 SQLite 事务中完成。

## 词库查询

`desktopQuery` 的 `kind=words` 支持下列字段：

| 字段 | 值与边界 |
| --- | --- |
| `scope` | `library`、`dictionary`、`catalog`、`book`、`trash`、`manual` |
| `sort` | `recent`、`alphabetical`、`source`；字典/词书默认来源顺序，个人视图默认最近更新 |
| `partOfSpeech` | `all`、`noun`、`verb`、`adjective`、`adverb`、`pronoun`、`preposition`、`conjunction`、`determiner`、`interjection` |
| `learningStatus` | `all`、`new`、`learning`、`review`、`mastered`、`unfamiliar` |
| `search` | 最多 100 字符，搜索词头和释义；转义通配符 |
| `offset` / `limit` | 0–1,000,000 / 1–100，默认每页 50 |

词性取只读派生表 `entry_parts_of_speech(entry_id,pos)`，来自 Dictionary 的真实义项。一个词可匹配多种词性。表不存在时，普通查询仍可使用；指定词性筛选时返回“索引正在准备”，不伪造成功结果。没有词性资料的自定义词仍显示在 `all`；Dictionary 频率排名不转成虚构的重要等级。计数和分页使用同一组筛选条件，返回 `total/offset/limit/words`，每行增加 `partsOfSpeech`。

我的词库 = 当前目标未回收引用 ∪ 主动采集/收藏活动词。只有产生个人内容、学习或回收事实时，目标词才会物化。回收目标不修改 Dictionary，公共字典页仍显示它；恢复纯目标词不会把它变成目标外收藏。

## 个人内容与词本命令

词条与词本统一使用正式写入口：`POST /api/desktop/command`。命令直接返回桌面状态，词条详情另用 `desktopQuery(kind=detail, wordId=...)` 读取。

- `collect` 收藏词，`capture` 另保存非空语境；可保存笔记与多词本归属，不接受 `meaning`。公共词的释义来自只读 Dictionary，新自定义词的释义为空。
- `saveNote` 只接受 `action/wordId/note/bookIds/expectedRevision`。`bookIds` 是最多 100 个词本的完整归属集合，省略表示不修改，空数组表示取消归属。`note` 省略也保持原笔记。
- `createBook` 接收 `name`，`deleteBook` 接收 `bookId`。系统词本受保护；删除普通词本时记录墓碑，个人词、遇见和学习事实保留，关联词的旧笔记草稿失效。

`tagIds`（包括空数组）、`tagId`、标签写命令与 `scope=tag` 明确返回 400；个人编辑不接受释义覆盖。旧 `/api/words`、`/api/books`、`/api/tags` CRUD 返回 404，宿主须调用正式命令，不做兼容转发。

正式领域 DTO 不包含 `personalMeaning` 或 `tagIds`。LMCP 的 `getWord.personal` 仅包含 `note`，采集 `annotation` 仅包含 `note`；未知旧字段即使为空也拒绝。插件通过 `recordEncounter/listNotebooks` 采集和读取词本，不管理词本或标签；公共释义与词形仍由 Dictionary 提供。

## 原子批量操作

```json
{"action":"bulkTrash","wordIds":["10000000-0000-4000-8000-000000000001"]}
```

每次提交的 `wordIds` 包含 1–100 个不重复 ID，同一单词的公共与个人身份别名也不能重复提交。单词操作 `trash/restore` 使用 `wordId`，同样支持虚拟目标词。

| 命令 | 行为与失败条件 |
| --- | --- |
| `bulkTrash` | 移入回收站；已回收项保持原样，不重复推进修订。 |
| `bulkRestore` | 恢复回收项；已活动项保持原样。恢复主动收录词时校验个人词库容量，纯目标引用不占该容量。 |
| `bulkAddToBooks` | 另传非空 `bookIds`，追加归属并保留原有关系；每词最多 100 个词本。回收词须先恢复，已回收词本或容量不足会使整笔失败。已存在关系不重复写入或推进修订。 |

上述命令在同一事务中处理；任一身份不存在、别名重复或不满足对应命令的条件时，词条、关系与修订全部回滚。批量命令按执行时的真实状态校验，不接收 `expectedRevision`，也不改写笔记或隐藏字段；个人内容编辑另以 `expectedRevision` 保护草稿。

用户确认、分页选择与按钮样式由宿主完成；Core 校验真实身份、来源和事务边界。回收/恢复会重建本机冻结队列，旧题与学习事件保留。采集和词本成员变动不覆盖已有模式；在当前模式点击重新开始时，读取新范围，其他模式继续使用自己的原范围。`practiceWords` 须携带 `mode` 读取该模式队列，`practice` 返回其 `cursor/sessionId` 与用于首入恢复的 `lastMode`。

## 规划预测

```json
{"kind":"planningPreview","goal":"exam:test","dailyNew":10,"daysAhead":5}
```

`dailyNew` 为 1–50；`daysAhead` 为 1–7、默认 5。返回：

| 字段 | 含义 |
| --- | --- |
| `total/learned/remaining` | 目标未回收词数 / 首次跨越 20 分完成初学的词数 / 尚未完成数 |
| `todayUsed/todayRemaining` | 当天已完成新学额度 / 请求计划每日额度扣除后的余额 |
| `dailyNew/days/endOn` | 每日额度、按此额度完成新学所需日历天数、预计最后一天 |
| `firstDays[].day/count/words` | 日期、完整当日预计数、最多 50 个 `{id,word,meaning}`；截取用 `wordsTruncated=true` |

请求的目标和每日额度与已保存值一致时，今日词取真实队列中的目标新学词；额外遇见可能先占用额度，目标新词因此可能为零。预览另一个目标或修改每日额度时使用该目标的来源顺序模拟。未来词排除今日已列项、已毕业词和回收词，保持稳定来源顺序。

例如剩余 25 词、每日 10、今日额度已用完，则今日预计 0，后三天是 10/10/5，预计四个日历日内完成。宿主可从当前 `learned` 画累计“预计完成新学”曲线。该图假设每天完成所选额度，不承诺 30 分熟悉状态、真实词汇量或 FSRS 复习负荷。

预览只读，不建立词条、日任务或学习事件，也不改变复习排期。关闭计划或更换目标不会抹掉笔记、语境和原学习事实。
