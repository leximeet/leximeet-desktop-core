# 快速开始

Core 是由 Desktop 管理的 Java 子进程。普通用户使用 Desktop 安装包；下面的独立启动用于开发和接口排查。

## 获取源码

在 [GitHub](https://github.com/leximeet/leximeet-desktop-core) 或 [Gitee](https://gitee.com/leximeet/leximeet-desktop-core) 获取本仓；两处使用同一套代码、构建命令和验证要求。下载正式版本时核对提交与附件 SHA-256，规则见[发布与验收](发布与验收.md)。

## 环境

| 工具 | 要求 |
| --- | --- |
| Java | JDK 21；Project SDK 和 Maven Runner 也使用 21 |
| Maven | 3.9+ |
| Python | 3.10+，只用于文档和真实 Jar 产物检查 |
| 网络 | 首次构建从公开 Maven Central 下载依赖，不使用机器私有仓库凭据 |

先运行 `java -version` 和 `mvn -version` 确认实际运行时。Core 启动和 Maven Enforcer 都会拒绝其他 Java 主版本，避免在错误的环境中生成个人资料。

## 构建

```bash
mvn -B -ntp -gs maven-settings.xml -s maven-settings.xml "-Dmaven.repo.local=.runtime/m2" clean verify
python3 scripts/verify-release.py
```

产物位于 `target`，Maven 缓存位于 `.runtime/m2`。这两个目录由 Git 忽略，可以重新生成，不用于保存个人资料。完整应用验收使用 Desktop 仓库的一键隔离脚本，见 Desktop 启动说明（[GitHub](https://github.com/leximeet/leximeet-desktop/blob/main/docs/本地测试启动.md) / [Gitee](https://gitee.com/leximeet/leximeet-desktop/blob/main/docs/本地测试启动.md)）。

## 启动参数

```text
java -jar target/leximeet-core.jar   --data-dir <本轮独占的绝对资料目录>   --token <32～256 字符的随机安全令牌>   --profile test
```

不要将真实令牌粘进 Issue、截图或文档。Desktop 在进程启动时生成独立 Core token，不向 Renderer 或 Browser 暴露它。可通过 `python3 scripts/verify-release.py` 自动创建临时令牌/目录并完成启动验证，省去手工清理。

| 参数 | 说明 |
| --- | --- |
| `--data-dir` | 必须是绝对目录；一个目录只允许一个 Core 写入者 |
| `--token` | 本机 Main 调用令牌；允许字母、数字、下划线、短横线 |
| `--profile` | production / development / test / demo；默认 production |
| `--seed-demo` | 只在 demo profile 显式导入示例 |
| `--seed-capacity` | 只在 test profile 创建 1–50,000 词容量夹具 |
| `--seed-note-length` | 只在 test 容量夹具中创建 1–8,000 字长笔记，词数最多 10,000 |
| `--test-clock-file` | 只允许 test profile 当前资料目录的 `test-clock.json` |

stdout 只输出一行握手 JSON，包含动态回环端口、profile、启动耗时等；诊断写入 stderr，不输出 token。退出时由宿主停止自己启动的子进程，禁止按进程名称杀死其他 Core。

## 本机调用

Main 使用握手端口，向 `http://127.0.0.1:<port>` 发送独立 Bearer token。网关拒绝网页 Origin、非本机 Host、非法 JSON、超限正文和未授权请求。端口每次启动可变化，不能写死。

`/health`、`/api/desktop/state` 和其他本机入口同样要求授权。Browser 使用 Native Host → Main → LMCP，不直接调用这些 HTTP 接口。接口责任见[核心职责](1.0.0核心职责.md)。

未安装公共词典时仍可启动空资料；要测试真实词卡和词书，请使用 Desktop 提供的固定 Dictionary 0.0.3 资源与挂载流程，不能把测试 JSON 当成完整词典安装。

## 启动失败的处理

Core 只向 stderr 输出一行安全诊断，包含固定错误码和最底层异常类型，不回显 SQL、私人正文、令牌或任意完整路径。Spring 的包装异常不再让用户只看到 `BeanCreationException`。

| 错误码 | 含义与处理 |
| --- | --- |
| `UNSUPPORTED_DATA_SCHEMA` | 资料版本与当前应用不同；原库保留，使用匹配版本或新的隔离目录 |
| `DATA_STRUCTURE_MISMATCH` | 同号旧实验结构、无版本资料或结构不完整；原库保留，不能自动修补 |
| `DATA_CORRUPTED` | 文件不是有效 SQLite 或损坏；保留原文件，从已验证备份恢复 |
| `DATA_IN_USE` | 同一资料目录被另一 Core 占用；关闭相同资料空间的另一实例 |
| `DATA_ACCESS_DENIED` / `DATA_DIRECTORY_INVALID` | 权限或目录不正确；检查用户资料位置 |
| `STORAGE_FULL` | 空间不足；腾出空间后重试 |
| `JAVA_RUNTIME_MISMATCH` / `INVALID_STARTUP_OPTIONS` | 使用随应用提供的 JDK 21 和宿主启动参数 |
| `INITIALIZATION_FAILED` | 未分类的初始化失败；记录错误码、原因类型和版本后提交问题 |

不要为消除错误而自动删除用户数据库。分享问题时只提供安全诊断和版本；备份及私人资料应继续留在本机。
