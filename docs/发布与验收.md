# 1.0.0 发布与验收

本仓首次正式版本和 Git 标签统一为 **`1.0.0`**，源码与正式附件的发布状态分别记录；存在 main 分支不表示正式标签或附件已经上传。应用、本仓 Core 和 LMCP 分别版本化；消费者冻结规范来源以随包记录为准，Desktop `core-java` gitlink 必须与最终核验的 Core 结果提交一致。正式版本在运行时按 API 主版本、最低要求与必需能力协商；构建时仍逐字节校验自身快照，详见[核心职责](1.0.0核心职责.md)。

## 历史本机候选验收

2026-10-05 的历史源码候选在 macOS arm64 / JDK 21 上运行 `clean verify` 共 **174 项、40 套**，失败、错误和跳过均为 0。覆盖纯规则、实际 SQLite/HTTP、Main 子进程、当前格式备份、学习事件重放、大小写语境查重、冻结范围真实题目，以及正式 note-only 合同的旧字段拒绝。大型冷冻结测试覆盖 117,902 / 811,092 词的真实 SQLite 队列，并检查顺序、个人关联、回收过滤及六模式复用；不增加页面请求超时。首次结构测试通过完整同号旧结构的安全拒绝，并核对原数据库 SHA-256 和笔记；当前结构创建、重开与备份恢复继续通过。

当时的真实可执行 Jar 另检查鉴权、当前资料命令、退休路由、四种坏/旧文件安全拒绝、17 个运行时组件的许可和 SBOM。这些计数和检查范围保留为历史记录，不作为本轮历史整理、更新来源后的最终提交或重新构建产物的验收。当前规范版本为 LMCP `1.0.0`；准确的 `sourceCommit`、逐文件摘要及来源版本查看 [src/main/resources/lmcp/source.json](../src/main/resources/lmcp/source.json)；本文不硬编码可随重新整理而改变的来源提交 SHA。

2026-10-04 的双端与用户人工验收是此前实现基线。Browser 包含在本轮 Desktop、Core、Browser 与 LMCP 的 `1.0.0` 准备范围内；更新来源后的新联合测试尚未执行，旧双端结果不能作为最终提交与正式 Schema 的联合验收结论。Desktop 本机 UI 和实际安装验证由 Desktop 仓记录。

Core 证据不能代替 OS 通知、真人输入法/声音、签名安装和其他平台的验证。正式协议稳定化、排版与构建门禁属于本轮收尾，新版本必须重新执行相应验证；不把前一应用包的 SHA 当成最终发布包 SHA。

## 首次公开历史与来源

首次公开整理保留各仓远端原始 `init commit`，将其后的开发历史压缩为一个当前结果提交。原始 init 的 SHA、作者与提交时间保持不变，不另建孤立根提交替换它。首次整理完成后，维护改动正常追加提交；不能为了维持两条提交而反复改写已公开历史。

已有完整开发历史保留在私有备份中，供恢复和追溯使用，不推送备份分支、旧候选标签或 Git bundle。公开前审查结果树、提交说明和引用，只推送明确批准的 main 与 `1.0.0` 标签，不使用 `git push --all` 或 `git push --tags` 批量公开其他历史。同步前分别核对两个平台的 main 与本地提交关系；若有新增贡献或分叉，先审查并整合，不能强制覆盖另一平台的历史。

正式标签创建前以精确提交 SHA 作为来源，不能将尚未发布的标签写成可下载的依据。正式发布后的来源以 Core `1.0.0` 标签、随包 [LMCP 来源记录](../src/main/resources/lmcp/source.json)、Desktop 固定 gitlink 和发行物的源码、构建及发布 manifest 为准。结果提交生成前不预写未来 SHA；新联合测试与最终 Jar 检查完成后，再记录实际版本、来源与产物摘要。本页不授权推送、打标签或创建 Release。

## GitHub 与 Gitee 发布

[GitHub](https://github.com/leximeet/leximeet-desktop-core) 与 [Gitee](https://gitee.com/leximeet/leximeet-desktop-core) 是平级发布和贡献入口。代码托管、CI、Git 标签与发行附件分别核验，某个平台已有仓库不代表其附件已经发布。

- 维护一条 main 历史，同一正式版本在两个平台指向同一提交；带注释的标签使用同一个标签对象，不在两边分别重新生成。
- 发布前改动尚未完成时，保留版本号 `1.0.0`，暂不创建正式标签。全部检查完成并获得维护者批准后，再对最终提交创建标签并明确同步目标；已经公开的正式标签不得移动覆盖。
- 两个平台上传同一批 Jar、完整源码、SBOM 与校验和，不各自重打同名不同内容的包；按本次发布清单逐项核对 SHA-256。
- 当前 CI 由 GitHub Actions 执行，Gitee 尚无随仓流水线。通过 Gitee 发布时也须核对同一提交的 CI 结果和本地验收记录；平台平级不等于 CI 状态自动同步。
- 若某个平台暂时不能上传附件，标明该平台尚未发布并提供已完成的平台入口，待附件核验通过后再更新状态，不把网页入口当成发行证明。

## 构建产物

| 文件 | 用途 |
| --- | --- |
| `target/leximeet-core.jar` | JDK 21 可执行 Core，保留嵌套依赖/许可 |
| `target/leximeet-core-sources.jar` | 同次构建的项目源码与资源 |
| `target/bom.json` / `bom.xml` | CycloneDX 1.6 运行时依赖 SBOM |
| `target/release-verification.json` | 本轮 Jar/源码/SBOM SHA、真实启动和隔离回收结果 |
| `target/surefire-reports` | 单元、事务、HTTP 与子进程报告 |

源码 Jar 供阅读 Java 源码和资源，不包含完整构建入口。正式分发还必须附同一提交的完整源码归档，包含 `pom.xml`、`maven-settings.xml`、测试、脚本、docs 和许可证，保证能够按本仓命令重建。

归档时间由 `pom.xml` 的 `project.build.outputTimestamp` 固定。更新正式版本时一并调整该时间；使用相同工具链重建并比较 Jar/源码 Jar 的 SHA，可以发现时间戳噪声，不能据此声称已经验证其他机器或平台的完全复现。SBOM 包含生成信息，其 SHA 按本次实际文件记录。配置依据见 [Maven 可复现构建指南](https://maven.apache.org/guides/mini/guide-reproducible-builds.html)。

它们由本地和 CI 生成；Actions artifact 不是自动正式 Release。不要提交 `target`、`.runtime` 或私有测试资料。

## 发布门禁

1. 全部本地格式/文档/Java/真实 Jar 检查通过，明确记录实际 SHA 和版本。
2. 对最终四仓提交运行远端 Actions；查看三平台实际结果，不能只看 YAML 存在。
3. Desktop 使用新 Core gitlink 与正式协议摘要，重新验证冻结契约、Native Host/Browser 连接和打包。
4. 核验对应源码、项目/依赖/词典/JRE 许可、SBOM、下载包校验和与 Git 历史公开范围。
5. Desktop 各正式平台的签名、安装、升级/回滚、系统通知权限和原生输入体验须另外通过验收。
6. 维护者明确批准后再创建 tag、上传 Release 或发布包；本轮不自动推送或发布。

发布说明描述实际功能、已测平台和限制，不包含机器路径、私人日志、对话、账号或虚构下载地址。首次正式版之后的兼容基线从 1.0.0 开始，未发布的 0.x 测试库不迁移。
