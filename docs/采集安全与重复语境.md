# 采集安全与重复语境

桌面手动记录、目标内剪贴板采集和连接插件的 `recordEncounter` 共用 Core 事务政策。Browser 独立运行时使用相同的算法与默认值；连接时以桌面返回的政策为准，不能用 Browser 独立偏好覆盖桌面。

## 设置

| 本机设置字段                       | 默认值 | 范围与作用                                             |
| ---------------------------------- | ------ | ------------------------------------------------------ |
| `captureDuplicateWindowDays`       | 7      | 整数 0–365；0 关闭时间窗口查重                         |
| `captureSensitiveRedactionEnabled` | true   | 布尔值；识别到的敏感内容替换为 `xxx`                   |
| `captureContextMaxLength`          | 500    | 整数 120–2000，单位是 UTF-16；保存目标所在句的有界窗口 |

Main 使用本机 `/api/settings` 保存。关闭插件成功通知是独立设置 `pluginCaptureNotificationsEnabled`，不关闭采集或脱敏。

当前 schema 100 的设置 JSON 缺少新增可选字段时，Desktop `state.settings`、本机 snapshot 和采集政策读取都会补足缺省值；优先使用已有用户值。读取时只生成结果投影，不修改原设置 JSON、资料修订或 schema。保存设置仍走原明确写入入口；这不是旧 0.x 库迁移。

LMCP `getWorkspace` 成功结果额外提供 `capturePolicy:{duplicateWindowDays,sensitiveRedactionEnabled,contextMaxLength}`。这是读取本机政策的安全摘要，不是远程设置接口。政策变化会使读取修订变化；本次采集结果还带实际使用的政策快照。冻结 LMCP 1.0.0 Schema、方法和身份字段不变。

1. 原句和摘录的范围必须准确指向实际 `surface`，不能用大小写归一的词头代替原文。敏感选区返回 `SENSITIVE_SELECTION`，不把秘密作为单词保存。
2. 邮箱、常见手机号/电话号码、18 位身份证样式、通过 Luhn 校验的银行卡样式、JWT 样式、密码/令牌字段值、Bearer 值及已知长密钥前缀按确定规则处理。笔记、来源标题和 URL 中的内容也按这些规则识别。
3. 先处理整段敏感跨度，再截取第一个所选位置所在的句子。中文句末标点和换行分句；英文句末标点需在结尾或后接空白/闭引号。邮箱域名和小数内部的点不会单独分句；敏感值后的句末标点保留。
4. 超长句围绕目标截取；不切开代理对，只保留窗口内的原选区，不臆造新的出现位置。原句字段与摘录字段均保存安全文本，没有另存未脱敏原文。
5. 剪贴板自动匹配和手动录入按词头寻找位置时，先忽略敏感位置，再取首个安全命中。`An apple arrived; password=apple. Next apple is ripe.` 可保存第一句并遮住密码值；用户明确选择密码中的 apple 时，仍会被拒绝。

规则匹配提供可复现的安全默认值，并不承诺识别全部自然语言隐私、未知密钥格式或 URL 编码后的秘密。用户关闭脱敏后的新采集保留实际内容；修改设置不批量改写之前保存的资料。

## 七天查重

判定键是“真实单词身份 + 安全摘录”。公共词沿 `entryId` 及本机显式关联判断，自定义词沿 `customId` 判断，不凭相同词头合并身份。

安全摘录先 NFC 规范化，再把 Unicode White_Space 连续空白折为一个普通空格并去掉首尾空格，最后按与语言环境无关的规则转为小写。这个步骤只生成查重键，原句、大小写、UTF-16 位置和已有遇见都不改写。标点、句子内容保留，来源网站、笔记、词本不参与语境键。

例如同一真实词条的 `Node connects an idea.` 与 `node connects an idea.` 在七天内只保留一次；`Node connects another idea.` 是不同语境，仍可保存。浏览器侧栏可把同词的多处出现合为一个列表入口，但不能因此删除不同句子的遇见或用显示词头替换公共 `entryId` / 自定义 `customId`。

窗口按 UTC 瞬间滚动计算，包含精确边界：已存时间位于 `[本次时间 − 7×24小时, 本次时间]` 才查重。到第七天同一时刻仍重复，超过边界才允许新建；撤销的遇见不占此窗口。不是“同一自然周”，也不是永久去重。

重复不会新增遇见、收藏归属、笔记、词本关系、积分、教学成功或资料修订。本次新笔记/词本不会借重复采集写入；需要编辑时使用桌面的明确编辑入口。

## 结果与重试

| 入口                    | 新建                                         | 近期重复                                        |
| ----------------------- | -------------------------------------------- | ----------------------------------------------- |
| 本机 `capture`          | `state.captureResult.captureStatus=created`  | `duplicate-context`                             |
| 本机 `captureClipboard` | `clipboardAccepted=true`，附 `captureResult` | `clipboardAccepted=false`，附 `captureResult`   |
| LMCP `recordEncounter`  | `captureStatus=created`、本次 eventId 实体   | `captureStatus=duplicate-context`、已有遇见实体 |

`captureResult` 或 LMCP 结果均带 `capturePolicy` 和 `entity`。实体主键字段是 **`entity.entityId`**。重复结果不是异常，也不是本次新采集成功；界面应提示“此语境近期已记录”。未启用剪贴板/目标已切换等不适用结果没有 `captureResult`。

重复回执按当前政策做安全投影，保留已有实体 ID、revision、身份和时间，不改历史实体。这样在“之前关闭脱敏、现在开启”时，也不会把旧秘密带进新的连接回执。重放原 mutation/event 时保留原结果和政策快照，不重新应用现在的偏好。

`mutationId` 的请求指纹以及 `eventId` 的内容指纹仍包括完整原意图；指纹只保存 SHA-256，不保存原明文请求。改变同一 ID 的原句、笔记、来源或词本仍属于冲突，不能通过时间查重覆盖已有回执。结果未知必须查询/重试原 ID。

剪贴板 `clipboardCandidates` 带 `text` 时先做安全预检，返回的 `matches[].context` 已脱敏、截句，并排除近期重复。Main 的通知队列只接收此安全语境；最终确认时事务内仍重新检查目标、开关与查重。预检不替代提交校验。

### 本机剪贴板操作回执

Main 提交 `captureClipboard` 时传入 `operationId`，格式为规范小写 UUID；通知项从第一次确认到失败重试使用同一个编号和同一请求。这个 Main 私有字段不属于 LMCP，也不是遇见实体 ID。

- 首次处理在同一 SQLite 事务中保存遇见及安全结果回执。回执只含原请求的 SHA-256 与处理后的 `captureResult`，不保留原敏感正文；不适用的撤回结果也有回执。
- 收到相同编号和请求时，先恢复原回执，响应顶层 `captureOperationReplayed=true`；不新增遇见、关系、积分、教学成功或资料修订。即使关闭七天查重，或之后改变目标/政策，也不重新执行原操作。`captureResult` 保持原政策快照与结果，不能把原 `created` 再算一次成功。
- 同编号更改正文、目标或单词时返回 409 `IDEMPOTENCY_KEY_REUSED`；事务失败没有半写入或成功回执，可以保留原编号继续重试。明确重新采集使用新编号，仍须重新通过开关、目标与语境政策。
- 回执复用 `lmcp_capture_events`，私有键为 `desktopClipboard:<operationId>`。公开 LMCP eventId 只能是 UUID，两类键互不占用；schema 100、文件备份结构及冻结 LMCP 1.0.0 协议不变。

Main 在系统模式下保存失败时会保留原项，显示一条“采集结果待确认”通知，点击“重试采集”才恢复原操作，不自动倒计时重写。弹窗模式有相同重试按钮。“关闭提示”只撤回当前提示，不能撤销可能已提交的资料；普通待确认且尚未保存的项仍可选择“不采集”。匹配/通知失败时，可在设置中明确重试：单次检查当前剪贴板，并重发失败项确认；系统仍不能投递时，此次用户操作才打开待处理窗口。

正常轮询不会将重新复制相同文本当作可靠的新动作，Electron 的跨平台接口没有统一复制序号。明确预检会记住本次已检查的正文，不清空去重缓存或改变轮询周期。关闭采集、改变目标或关闭待处理窗口会撤回本机内存队列，已保存的资料仍保留；本轮不提供系统瞬态通知的跨进程 UI 恢复。Core 回执持久化，只有保留原编号与请求才能恢复它。

## 验证边界

Core 的共享向量位于 `src/test/resources/capture-policy-v1.json`；包含句界、邮箱句末、密码值句末、Unicode 空白、敏感选区、超长窗口、代理对和不区分大小写的语境键。真实 SQLite 测试覆盖三种采集入口、精确七天边界、0 关闭、跨来源、政策切换安全回执、相同文字不同身份以及重放。隐私回归扫描全部个人表文本列，包括失败/重复操作回执，验证开启脱敏时新测试秘密没有落库。

完整浏览器跨进程、剪贴板通知与应用替换验收由 Desktop/Browser 各自记录，不能用纯 Java 测试代替平台通知验收。
