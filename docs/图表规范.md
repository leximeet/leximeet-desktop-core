# 图表维护规范

图表采用浅蓝圆角节点、蓝色文字、细灰连线和胶囊式分支标签。暗色版本使用深蓝背景与高对比文字，不依赖网页或 GitHub 自带主题修改图形。

## 源码与展示

- `diagrams/*.mmd` 是每张图的可编辑源；正文的折叠源码与它保持一致。
- `diagrams/rendered/*.light.svg`、`*.dark.svg` 是同一源生成的展示文件。正文 `picture` 根据用户主题选择。
- `diagrams/sources.json` 记录图源、正文与来源；`rendered/manifest.json` 记录 Mermaid 版本、主题以及源/输出 SHA-256。
- 流程图只用于表达关系和分支。判断使用圆角虚线节点；图的形状不承担额外业务含义。

GitHub 的普通 Mermaid 围栏由 GitHub 自己渲染，无法被另一个网站的 CSS 统一。因此正文先显示可核查的 SVG，标准 Mermaid 源放在折叠区，供修改和复用。规范合同的原始正文如已冻结，只在图解伴随页展示相同语义，不为美化改变规范字节。

## 修改一张图

1. 修改对应 `.mmd`，保留明确的参与者、责任和成功/失败分支；同步正文折叠区的同一源码。
2. 使用文档站仓库的 `scripts/render-doc-diagrams.mjs --repo` 对本仓生成明暗 SVG；渲染器只访问本机服务，不使用 CDN、外部字体或个人资料。
3. 检查两种主题和窄屏下文字、连线与分支标签，更新 manifest 后一起提交源、正文与输出。

共享渲染器、具体命令和视觉参数见[文档站图表规范](https://github.com/leximeet/leximeet.github.io/blob/main/docs/设计文档/图表规范.md)。无需为应用运行增加 Mermaid 或浏览器依赖；这些工具只用于维护文档。

禁止在图源加入 `init` 指令、HTML、脚本链接、任意 `click`、局部 `style` 或 `classDef` 覆盖。用纯文本标签和标准关系表达业务，由统一渲染器设置配色、安全级别和布局。复杂系统按进程、业务事务、数据关系拆图，避免一张图堆几十个节点。
