# 安全与隐私

## 信任边界

- Java Core 只监听动态回环端口；本机 Main token、LMCP pairing/session/host grant 是不同凭据。
- 网页不能直接访问 Core HTTP；Native Host 提供可信扩展 origin，不能信任正文自报身份。
- 连接期间，独立 Browser A 保持封存；网络错误或撤权时不能擅自写入 A，只有可信且明确的断开操作才能恢复。
- 词典和冻结 Schema 是受校验的只读资源；第三方词条中的 Markdown/HTML 由宿主安全渲染，不执行代码。
- 普通采集默认脱敏，只保留目标所在单句，并限制长度；日志及回执不保存原秘密。规则不是完整隐私识别器，详见[采集政策](采集安全与重复语境.md)。

攻击者完全控制本机账户权限时，可能读取资料或进程；当前没有个人 SQLite 文件加密方案。不要把“回环鉴权”宣传为抵御已控制同一账户的一切攻击。

## 数据处理

本仓没有遥测、云登录或远程同步功能。个人 SQLite、备份和诊断资料由宿主和用户保管；禁止把这些作为公开错误附件。采集源 URL、注释和标题也属于隐私边界。关闭脱敏会影响之后的新采集，不会批量重写既有资料。

备份导出剥离授权；恢复不复制他人有效凭据。测试只用自有临时资料和受控业务时钟，不修改 OS 时间或读取正常用户资料。

## 漏洞报告

GitHub 与 Gitee 的漏洞报告采用同一处理原则。GitHub 已启用私密漏洞报告时，在 Security 页面使用 **Report a vulnerability**；使用 Gitee 或没有私密入口时，先通过维护者明确提供的私密渠道联系。尚无渠道时只在公开 Issue 请求安全沟通，不提交利用脚本、真实密钥或私人正文。具体入口见 [安全政策](../SECURITY.md)，不假定两个平台具备相同的私密功能，也不承诺尚未建立的安全邮箱、奖励或响应时限。

报告包括受影响版本、最小可复现条件、影响与脱敏证据。维护者确认后协调修复和披露。准备支持的基线为 1.0.x；1.0.0 尚待正式发布，预发布测试结构没有兼容承诺。

## 发布前检查

核实 Git 历史与待发布归档，不只检查最新工作树。发现真实凭据先撤销/轮换；历史压缩或重写必须经仓库所有者明确决定，不能用删除当前文件来冒称历史已净化。检查依赖 SBOM 与实际许可；提供 SBOM 并不证明没有漏洞或权利问题。
