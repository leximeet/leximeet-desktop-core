# 版本与兼容

LMCP 合同与 API 均为 **1.0.0**。当前工作是发布准备，仓库验证、应用验收和 GitHub 正式 Release 分开判断。应用旧候选的本机连接语义已验收；消费端须切换到本次交付身份再回归。

## 版本分工

| 版本 | 管理内容 |
| --- | --- |
| API 版本 | 方法、字段、权限及兼容范围 |
| 合同交付版本和摘要 | 本次规范物料的精确身份 |
| 应用版本 | Desktop、Core、Browser 各自构建 |
| Dictionary 版本 | 只读词典与词书资源 |
| LMSP 版本 | 后续云同步，不是本机连接依赖 |

```mermaid

  A[合同 1.0.0] --> B[各端固定交付身份]
  B --> C[真实 Native 链路回归]
  C --> D[平台安装与人工验收]
  D --> E[维护者批准发布]
  E --> F[正式用户资料升级保护]
```

## 兼容规则

正式版本按 API major、最低服务版本和必需能力判断连接。新增可选方法、响应字段或宿主扩展不强制所有客户端同时升级；请求仍严格拒绝未知字段。改变既有字段含义、权限、数据归属或删除必需能力需要新的 major。不同摘要不能单独作为正式版本拒绝连接的理由。

第一次 1.0.0 之前的 rc/0.x 是隔离测试资料，不做旧候选双栈或迁移。第一次正式发布后，活动库与封存独立库同属用户资料；升级必须保护身份、事实、笔记、单词本及未确认命令。无法继续使用的能力须明确提示，不能静默丢资料。

## 改合同的步骤

1. 明确是否改变已有语义，以及消费端影响。
2. 同步修改方法表、Schema、样例、规范文字与行为测试。
3. 若增加规范文件，明确加入 tools/contract-digest.cjs 的清单。
4. 运行 npm run contract:generate 和 npm run verify。
5. 消费端固定新身份，分别验证单端、真实连接、恢复和安装物。

新增索引、维护、贡献、发布或路线说明不改合同摘要；规范清单中的文字即使只改排版，也会改变交付摘要。完整共享模型在 LMSP 维护，LMCP 的 reading-domain 快照按生成规则保持同哈希。
